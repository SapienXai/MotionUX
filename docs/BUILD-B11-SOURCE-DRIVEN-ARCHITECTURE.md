# Build B11 source-driven generation

The Create app action on /build starts a managed job. Native Codex extracts user jobs and search queries through the bounded, read-only bridge. Brain searches the verified index. The resolver opens eligible prepared registry payloads, checks pins and notices, walks local imports, then supplies bounded implementation excerpts and any prepared example. The second native response proposes the application's navigation, data structure and interactions, selects supported upstream APIs and proposes an interaction program where composition is needed.

The canonical source graph owns routes, instances, entity fields, seed data and authored design and motion settings. A page projection supplies titles and routes to the legacy store and Preview host. The source renderer uses the graph and project modules directly. Existing starters and reviewed Blueprints retain their own editor and renderer.

The compiler emits adapters and per-instance TSX for generated compare, detail, grouping and time-review programs. Generated code renders its cited source through an adapter and binds it to project data. Export links requirements to instances and distinguishes unchanged upstream files, adaptations and synthesized artifacts. The project digest binds the graph, source pins, compiler, npm lock, assets and artifact hashes. Changed compiler or catalog bytes require regeneration. Archiving executable closures across future compiler versions remains open.

The current API profiles cover tabs, time slots, grouped disclosure, contextual disclosure, panel transitions, numeric feedback and selection highlights. Source bytes and local imports are fingerprinted. Rights, dependencies and explicit asset closure are checked before sending source context or exporting it. Adapters normalize import paths and apply type-only React 19 compatibility where needed. The ZIP retains the provider notices.

Jobs persist actual analysis, selection, composition, build and verification status. One generation runs at a time. The host supports cancellation and one bounded repair from verification feedback. The candidate becomes a managed project after matching routes load in the isolated browser. Natural-language revision starts from a saved version and must retain data definitions and selected sources. The previous revision remains recoverable.

The source editor uses a typed outline and a real Next.js iframe on port 5202. Properties can show an unsaved draft. Run and export use the saved revision. Session undo/redo and draft recovery apply to edits. Browser-local records use an application ID across page reloads and revisions.

The signed-in Codex service receives the brief and eligible code excerpts. Private catalog files and native evidence remain ignored in Git. The application deploys no service and connects to no production data.
